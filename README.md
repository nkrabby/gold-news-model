# Gold News Lab

A reproducible event-study and machine-learning MVP for estimating how major US economic releases affect **XAUUSD** over 5 minutes, 15 minutes, 1 hour, 4 hours, and 24 hours.

This is an analyst's research tool, **not** a claim of certain prediction or financial advice.

## What it does

1. Downloads US calendar records (actual, consensus forecast, previous, UTC release timestamp).
2. Downloads public five-minute XAUUSD bid candles from Dukascopy.
3. Aligns every release with the last available pre-release price and subsequent prices.
4. Calculates a robust, point-in-time standardized surprise:
   `surprise = actual - consensus`.
5. Flips the surprise sign where a stronger release is normally bearish for gold. Higher unemployment is treated as gold-bullish; hotter inflation, stronger payrolls, and higher rates are treated as gold-bearish.
6. Adds pre-event gold trend and volatility.
7. Fits regularized logistic regression for direction and ridge regression for return magnitude.
8. Evaluates on releases from **2025 onward**, while fitting only on pre-2025 observations.
9. Provides an interactive scenario analyzer, historical event explorer, and validation dashboard.
10. Lists scheduled upcoming releases, generates conditional beat/miss scenarios, and collects timestamped research links. Research headlines are discovery aids—not verified facts or model inputs.
11. Produces a prominent **pre-release probabilistic forecast**: bullish/bearish/neutral, P(up), P(down), expected move, an 80% model range, expected actual, and P(actual beats consensus). A two-stage ridge/reaction model integrates the unknown data-surprise distribution. An optional analyst research tilt is explicit and separate from the statistical baseline. Pre-release validation is reported independently in `outputs/pre_release_models.gold_metrics.csv`.
12. `Gold_News_Dashboard.html` is a fully self-contained offline browser export generated by `src/export_standalone.py`.

## Upcoming-event workflow

Open **Upcoming event** and select a scheduled release. Enter or confirm the working consensus, then compare stronger, in-line, and weaker hypothetical outcomes. Review the linked original research, official source, Fed pricing, DXY/yields, positioning, and simultaneous releases. The research feed comes from Google News RSS and stores links/headlines only; it does not automatically trust or trade on article sentiment.

## Run locally

Python 3.11+ and Node.js 18+ are recommended.

```bash
cd gold_news_model
python -m pip install -r requirements.txt

# Refresh source data (optional; raw data is already included)
python src/fetch_calendar.py --start 2020-01-01 --end 2026-11-11
bash src/fetch_prices.sh 2020-01-01 2026-11-11

# Rebuild and validate
python src/build_dataset.py
python src/train.py

# Open dashboard
streamlit run app.py --server.address 0.0.0.0
```

Open `outputs/research_report.html` for the static report. Core outputs:

- `data/processed/event_study.csv`: event features and realized reactions
- `outputs/models.joblib`: fitted pipelines
- `outputs/out_of_sample_predictions.csv`: test predictions
- `outputs/metrics.csv`: validation and trade diagnostics
- `outputs/event_statistics.csv`: event/horizon conditional statistics

## Reading the output

- **Surprise σ** compares a consensus miss with the rolling median absolute consensus error for that event. The rolling window contains only earlier releases.
- **Gold-bullish/bearish** is a first-order macro interpretation, not a forecast. For example, a payrolls beat is signed gold-bearish.
- **P(XAUUSD up)** is a model probability; values near 50% mean low conviction.
- **Expected return** is a model mean, not a target or confidence interval.
- **MFE/MAE** are the maximum favorable/adverse high-low excursions in the event window.
- Trade diagnostics use a five-minute-delayed reaction and an arbitrary 3 bps round-trip cost. They are not a portfolio simulation.

## Important limitations

- The initial out-of-time result is weak: this MVP should be treated as a benchmark to improve, not a production signal.
- Only around 196 events per horizon are in the held-out period. Regime changes and overlapping same-time releases make effective sample sizes smaller.
- A free consensus calendar can contain corrections, missing values, and revised previous values. Raw files are retained for auditing.
- FOMC consensus frequently falls back to an unchanged-rate proxy. The model does not read statements, projections, or Powell's press conference.
- Returns begin at the last pre-release bid close. Capturing that move in live trading is generally impossible after the number is public. The delayed-return diagnostic is more relevant but still ignores realistic fast-market slippage.
- Spot gold is OTC; another broker's quotes can differ. Bid-only bars do not model the ask spread.
- A single chronological split is not enough for deployment. Add walk-forward evaluation and a forward-release log before drawing stronger conclusions.

## Data sources

- Dukascopy instrument history and downloader: https://www.dukascopy-node.app/instrument/xauusd
- TradingView public economic-calendar endpoint used by `src/fetch_calendar.py`: https://economic-calendar.tradingview.com/events
- BLS release information: https://www.bls.gov/schedule/news_release/
- Federal Reserve FOMC calendars and statements: https://www.federalreserve.gov/monetarypolicy/fomccalendars.htm

The calendar endpoint is public but unofficial and may change. Respect source terms and retain attribution. Official BLS/Fed data can be used to audit actual values and timestamps, but official agencies do not publish economist consensus forecasts.

## Sensible next iterations

1. Add DXY and US 2-year/10-year yield reactions as explanatory variables.
2. Build a combined NFP report feature set instead of treating payrolls, wages, and unemployment as independent events.
3. Parse FOMC statement/press-conference language with a time-stamped text model.
4. Use walk-forward retraining, event-block bootstrap confidence intervals, and probability calibration.
5. Add broker-specific bid/ask data and realistic news execution before any trading backtest.
6. Keep a forward log of predictions and outcomes without refitting on the release being evaluated.

## Two forecast numbers, and which one counts

Under **Pre-event analyst workspace** the dashboard shows:

1. **PIPELINE CALL (frozen)** — produced by `src/pre_release.py` with live market context and
   Forex Factory consensus, then written to `outputs/forecast_log.csv`. This is the number to score.
2. **Interactive what-if** — recomputed in your browser from the consensus, trend and tilt
   inputs on the page. It exists so you can ask "what if consensus were different?", and it
   will usually disagree with the pipeline call slightly.

If the two differ, the frozen pipeline call is authoritative. The what-if is a sandbox.
